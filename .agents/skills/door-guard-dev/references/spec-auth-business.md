# 认证业务规格与状态管理(主页验证的核心逻辑)

> 本文是主页验证业务的**唯一权威**;UI 呈现细节配合 spec-ui.md 一起读。
> 核心思想:用少量标志位 + 单一状态机管理所有异步事件(摄像头检测、识别结果、触摸、超时),
> 任何时刻每个事件的行为都由状态唯一确定,不允许散落的 if。

## 1. 状态机

```
ST_NORMAL ──点菜单──▶ ST_ADMIN_AUTH ──5s超时──▶ ST_NORMAL
   │  ▲                │    │(管理员通过)
   │  └─超时/失败退回───┘    ▼
   │                    ST_MENU
   │(点验证)
   ▼
ST_VERIFY ←──每步 5s 超时/用户取消──(各子步)
   │
   ├─ v_input_uid     弹窗输入用户 ID
   ├─ v_pick_method   显示该用户开启的方式按钮
   ├─ v_face_1v1      1:1 人脸
   ├─ v_finger        请按指纹
   ├─ v_pwd           输入密码
   └─ v_ic            请刷卡
任何子步成功 → ST_RESULT(绿色,约 3s 自动回)→ ST_NORMAL
任何子步失败 → ST_RESULT(红色,约 3s 自动回)→ ST_NORMAL
```

标志位(建议,放 `ui/page_home.c` 或验证上下文结构体):

| 标志 | 含义 |
|---|---|
| `app_state` | 上述状态机当前态(单一事实来源) |
| `match_enabled` | 1:N 人脸匹配开关;进 ST_VERIFY 即关,回 ST_NORMAL 才开 |
| `popup_active` | 有弹窗在显示;期间屏蔽其它页面级按钮输入 |
| `detect_enabled` | 人脸检测+画框开关(与 match_enabled 独立:弹窗期间检测继续、匹配停止) |
| `timer_seq` | 每次进入新状态/新子步 +1;超时回调比对 seq,过期定时器直接丢弃(防旧定时器误杀新状态) |

## 2. 普通验证模式(ST_NORMAL,默认)

1. 摄像头实时画面持续显示;检测到人脸 → **黄色框**实时跟随
2. `match_enabled=1`:1:N 人脸检索,**只在"role≠2 且 auth_flags 含人脸"的用户中检索**
3. 命中 → 框变**绿色** + 绿色成功弹窗(用户 ID、用户名称)→ access_service 开门 → 日志(result=0)
4. 检测到脸后 **1.5s** 内未命中 → 框变**红色** + 红色失败弹窗 → 日志
   - 库里没有该脸 / 该用户未开启人脸 → reason=1 陌生人(对外统一显示"验证失败")
   - 命中黑名单 → reason=2 黑名单(同样红色失败;可配置告警,预留)
5. 一次判定周期结束后(弹窗关闭)恢复检测;判定期间不重复弹窗

## 3. 管理员验证模式(ST_ADMIN_AUTH)

- 入口:主页点"菜单"按钮;屏幕下方提示"管理员认证"字样
- 人脸路径:检测到人脸后在 **role=1 的管理员**中检索(1:N,可多管理员;1:1 亦支持——
  若管理员在验证页输入过 ID 则走 1:1,未输入走 1:N,两条路径都放行)
- 通过 → 进菜单页面(ST_MENU);非管理员/陌生人 → 红色失败弹窗,**停留在本模式**继续尝试
- 点"验证"按钮:走 §4 流程,验证通过后校验 `role==1`,是则进菜单,否则红弹窗
- **5s** 内无人脸且未点"验证" → 自动回 ST_NORMAL(提示文字随之消失)

## 4. "验证"按钮流程(ST_VERIFY,各子步)

前提语义:用户点了"验证"即**放弃主页默认 1:N 人脸验证** —— `match_enabled=0`,
摄像头照常工作、脸框照常画,但不再做 1:N 检索、不弹普通模式的结果。

1. **v_input_uid**:弹窗输入用户 ID
   - ID 不存在 → 红弹窗"验证失败"(reason=5),退回 ST_NORMAL
   - 黑名单 → 红弹窗(reason=2),退回
   - `auth_flags==0`(全部验证方式关闭)→ 红弹窗(reason=8),退回
2. **v_pick_method**:按该用户 `auth_flags` 显示对应按钮:1:1 人脸 / 指纹 / 密码 / IC 卡
   (只显示开启的;至少有密码,见 spec-database)
3. 各方式子页:
   - **1:1 人脸**:关弹窗,画面提示"请正对摄像头",特征与该用户比对 → 成功/红弹窗
   - **指纹**:弹窗"请按指纹",等待指纹模块结果(超时即失败退回)
   - **密码**:弹窗数字键盘,输入显示 `*`;ID+密码验证(密码错误计入连错锁定,见 §5)
   - **IC 卡**:弹窗"请刷卡",等待读卡事件,卡号匹配该用户即成功
4. **每步 5s** 无用户操作/无模块反馈 → 取消本流程,回 ST_NORMAL
5. 成功 → 绿弹窗(ID、姓名)→ 开门 → 日志;失败 → 红弹窗 → 日志

## 5. 全局规则与边界(实现时逐条自测)

- 弹窗渲染在高图层,背后摄像头推流**持续刷新**(LVGL:推流 canvas 在底层定时刷新,不因弹窗暂停)
- 任意时刻只有一个弹窗;新验证请求先取消旧流程(清理定时器、复位标志)
- 超时统一用 `timer_seq` 机制:状态迁移使旧定时器全部失效,禁止"上个状态的 5s 超时把新状态拉回去"
- 验证成功后开门时长 `door_open_ms`(device_config),期间重复验证请求忽略但不报错
- 密码连错锁定:同一 user_id 连续错 N 次(默认 5)锁定 S 秒(默认 60),期间密码方式直接提示锁定;锁定计数掉电可丢(内存即可)
- 黑名单命中任何路径都失败并落日志;陌生人(无 ID)落日志 user_id=NULL
- 摄像头断流/识别服务未就绪:主页显示"摄像头未就绪"占位,所有验证路径立刻失败(reason=9),不得卡死等待
- 开机默认回到 ST_NORMAL;待机唤醒后也是 ST_NORMAL(不恢复之前的验证中间态)
