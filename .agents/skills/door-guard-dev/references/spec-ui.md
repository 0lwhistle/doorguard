# UI 规格(LVGL,蓝白主题)

> 平台:同一份 UI 代码跑两处 —— RK3576(DRM 后端,板上)与 **PC 模拟器**(SDL2,调 UI 用)。
> 摄像头帧通过 camera 模块(`modules/camera`)抽象注入:板上取真实流,PC 端用视频文件/图片源回放。

## 1. 主题与组件规范

色值 token(定义 `ui/theme.h`,全项目只引用 token 不写裸色值):

| token | 值 | 用途 |
|---|---|---|
| `DG_COLOR_PRIMARY` | `0x1E88E5` | 主蓝:按钮底、标题栏、选中态 |
| `DG_COLOR_PRIMARY_DARK` | `0x1565C0` | 按钮按下态 |
| `DG_COLOR_BG` | `0xFFFFFF` | 页面底色 |
| `DG_COLOR_BG_LIGHT` | `0xE3F2FD` | 卡片/分区底 |
| `DG_COLOR_TEXT` | `0x212121` | 主文字 |
| `DG_COLOR_OK` | `0x2E7D32` | 成功(绿) |
| `DG_COLOR_ERR` | `0xC62828` | 失败(红) |
| `DG_COLOR_WARN` | `0xF9A825` | 脸框黄(检测中) |
| `DG_COLOR_SCRIM` | `0x000000` | 推流/照片上的文字衬底(半透明黑 chip) |

- **层次感 token(2026-09-22)**:`DG_OPA_SCRIM`(衬底 40%)、
  `DG_OPA_CARD_LINE`(卡片半透明白描边 60%)、`DG_OPA_TEXT_DIM`(次要文字
  50%)——行标题/「无」占位值降透明度,卡片与按钮加半透明白边,推流上的
  时钟/网络/提示文字一律加黑色半透明衬底 chip
- **每个按钮 = 图标 + label**:统一 `ui/widgets/dg_btn_create(icon_sym, label)` 创建,
  图标优先用 LVGL 内置 symbol(如 `LV_SYMBOL_SETTINGS`),不合适用户后续会换
  (例外:菜单宫格卡片为页内自定义组件——浅蓝底+白描边,按下变主蓝)
- 所有 label 文本一律 `_("原文")` 包裹(`ui/i18n.h` 提供 `_()`)
- 弹窗统一走 `ui/widgets/dg_popup.h`:`dg_popup_success() / dg_popup_fail() / dg_popup_input() /
  dg_popup_choice()`,自动处理图层、自动关闭定时、回调

## 2. 多语言(i18n)

- 翻译文件:`ui/lang/zh-CN.json`、`en-US.json`(可扩展),**键 = 原文 label,值 = 翻译**
- `_()` 运行时查当前语言表;缺键回退原文并打 WARN 日志(方便发现漏翻)
- 语言切换(设备管理->语言)立即生效:发 event_bus 事件,各页面重刷静态文本

## 3. 三个页面

### 3.1 主页面(默认页,ST_NORMAL/ST_ADMIN_AUTH/ST_VERIFY 所在地)

- 背景:摄像头实时推流(NV12 → RGA/DRM 上屏,或模拟器下视频源);LVGL 只叠 UI 层
- 脸框 overlay:黄=检测到;绿=1:N/1:1 命中;红=失败/陌生人/黑名单(跟随人脸矩形)
- 下方两个按钮:**菜单**(左下,`LV_SYMBOL_SETTINGS`)、**验证**(右下,`LV_SYMBOL_OK`);
  行为见 spec-auth-business.md
- 弹窗全部高图层,推流不中断
- 顶部窄条(可选):时间、网络状态图标、NTP 已同步标记

### 3.2 待机页面

- 进入条件:**仅在主页面(ST_NORMAL)计时**——菜单/验证/结果中途不进待机;
  每次回到主页面倒计时重新开始。阈值 **待机超时**(15~60s,默认 30,
  设备管理页可调)内无检测到人脸且无触摸操作
- 表现:基本全黑,屏幕中央只显示时间(HH:MM,每秒刷新)
- 唤醒:任何触摸 / 检测到人脸 → 回主页面并重置无操作计时
- 菜单会话(ST_MENU,含其下用户/设备等子页)**15s 默认**无触摸自动回主页面
  (**菜单超时**,5~120s,设备管理页可调)——离开配置界面防"停死"在子页(2026-09-21)

### 3.3 菜单页面(仅管理员,从 ST_MENU 进入)

四个入口(宫格,图标+label):

| 入口 | 功能 |
|---|---|
| 用户管理 | 添加/编辑/删除用户;字段:ID、姓名、密码(必填)、人脸/指纹/IC 录入、权限(普通/管理员/黑名单)、验证方式开关;冲突提示对照 spec-database 错误码 |
| 设备管理 | 语言切换;设备时间设置;**NTP 时间矫正按钮**(点一下真触发一次,用设备配置里的 ntp_server,结果经事件回来显示成功/失败——**不让用户在面板上现填服务器地址**);网络配置(DHCP 开关、IP/掩码/网关,改动即生效并落库);**待机超时**(15~60s)与**菜单超时**(5~120s)选择器,改完即生效(tasker tick 同步进 FSM,2026-09-21) |
| 门禁设置 | 预留页,先放:开门时长、密码连错锁定参数(均落 device_config;后续按需求扩展)。待机超时已迁往设备管理页(2026-09-21) |
| 记录查询 | 按时间段(+可选用户 ID)查 access_logs,列表分页显示:时间/ID/姓名/方式/结果 |

通用:每页有返回按钮回上一级;页面栈深度固定,不做复杂导航。

**空库引导**(spec-auth §3):库里一个管理员都没有时,点"菜单"免认证进入本页,
并在进入后弹一次提示「未设置管理员,请先添加管理员」(红色,3s 自动关)。
这条提示由菜单页承接(切页事件在前),不在主页提示条上显示。

## 6. 验证流程的弹窗与文案(spec-auth §4 的 UI 侧)

### 6.1 屏幕键盘(触摸屏唯一输入手段,`ui/widgets/dg_kbd.*`)

无物理键盘:所有文本输入都走弹窗内嵌的屏幕键盘,两页可切换:

| 页 | 键位 | 用途 |
|---|---|---|
| 数字页(默认) | 1-9 / ⌫ / 0 / OK | 用户 ID、数字密码(门禁最常见) |
| 字母页 | QWERTY 三排 + ⇧(大小写)+ 空格 / ⌫ / OK | 英文姓名、字母密码 |
| 页脚 | ABC ↔ 123 切页 | 两页之间切换(切页复位大小写) |

- 键盘初始页由调用方指定:`start_alpha=false`(ID/密码)或 `true`(姓名)
- **中文不支持**:没有输入法;中文姓名只能在设备上"显示"(上位机录入),设备端可输英文/数字姓名
- 键宽按百分比分配(卡片宽 660),不依赖固定像素

### 6.2 输入合法性检测(每个输入都要过,`ui/valid_ui.c` + `proto/valid.h`)

- 规则见 spec-database §2.1;UI 侧在**按 OK 时**校验,不合格 → 弹窗内红字提示、
  **不提交、也不关闭**(用户可就地改),同时把输入长度**上限**直接设在 textarea 上(打不进超长值)
- 错误文案示例:「ID 需 3~31 位字母、数字、- 或 _，且以字母或数字开头」/
  「密码需 4~31 位，不能含空格」/「姓名需 1~63 字节，不能为空或前后带空格」
- 存储层同规则再校验一次(权威兜底);UI 的"通过"只代表格式合法,业务冲突
  (ID 重复/上限/查重)仍以服务层错误码为准并弹对应红字

### 6.3 验证流程的弹窗

弹窗全部走 `ui/widgets/dg_popup.*`(同一时刻只有一个;背景推流不冻结):

| 步骤 | 弹窗 | 回执事件 |
|---|---|---|
| 输入用户 ID | `dg_popup_input`("请输入用户ID",非掩码,数字页起,`validate=uid`) | 确认 → `EV_UI_TEXT_INPUT{UID}`;取消 → `EV_UI_BTN{BACK}` |
| 选验证方式 | `dg_popup_choice`("验证方式",选项=该用户开启的方式) | `EV_UI_METHOD_PICK`;只有一种方式时不弹窗直接进 |
| 输入密码 | `dg_popup_input`("请输入密码",**掩码**,`validate=pwd`) | `EV_UI_TEXT_INPUT{PWD, uid 原样回填}` |
| 1:1 人脸 / 指纹 / IC | 不弹窗,主页提示条给引导("请正对摄像头/请按指纹/请刷卡") | 由视觉/指纹/读卡模块回结果 |
| 结果 | `dg_popup_success`("验证成功 姓名",3s)/ `dg_popup_fail`(原因文案,3s) | — |

**失败原因 → 文案映射**(`presenter_home.c`,reason 见 spec-database §4):

| reason | 文案 |
|---|---|
| 5 用户不存在 | 用户不存在 |
| 3 密码错误 | 密码错误 |
| 6 该方式未开启 | 该方式未开启 |
| 8 全部验证方式已关闭 | 全部验证方式已关闭 |
| 9 设备异常 | 摄像头未就绪 |
| 1/2/4/7(陌生人/黑名单/不匹配/超时) | 验证失败(对外统一措辞,不泄露是否已录入) |
| 管理员入口的非管理员 | 非管理员(专用提示,不涉及录入信息) |

理由:用户自己输入的 ID/密码,提示具体原因能减少无效重试,也不泄露他人是否在库;
只有"陌生人/黑名单"这类涉及他人身份的才统一成"验证失败"。

**脸框颜色有两个来源**:视觉后端发黄色检测框(逐帧、跟随人脸),FSM 在命中/失败时发
`EV_UI_FACEBOX` 改颜色(绿/红),位置仍用检测框——框位不因服务层决策而抖动。

新增文案键:「非管理员」「未设置管理员,请先添加管理员」「验证方式」
(改 lang/*.json 后必须跑 `ui/font/gen.sh` 重生成中文字体,否则缺字形(i18n 测试会报))。

## 4. 实现组织

```
door-guard/ui/
├── theme.h            色值/字号/间距 token
├── i18n.h/.c          _() 与语言表加载(json)
├── lang/              zh-CN.json en-US.json
├── widgets/           dg_btn / dg_popup / dg_kbd(数字键盘)/ dg_list
├── page_home.c        主页面(含验证状态机,逻辑见 spec-auth-business.md)
├── page_standby.c     待机页
├── page_menu.c        菜单主页
├── page_users.c       用户管理
├── page_device.c      设备管理
├── page_access_set.c  门禁设置
└── page_logs.c        记录查询
```

- 页面间跳转走页面管理器(`ui/page_mgr.h`:push/pop),事件经 event_bus 发布订阅
- UI 层**不做业务决策**:按钮事件发事件给 access/enroll 服务,结果经事件回 UI 渲染
- PC 模拟器构建:`cmake -DDG_SIM=ON`(SDL2 窗口 720×1280),与板上共用全部 ui/ 代码;
  模拟器专用输入源(视频/图片循环)由 camera 模块(`modules/camera`)的 sim 后端提供

## 5. 验收自检(UI 相关,每次提交 UI 改动前过一遍)

- 所有文本 `_("")` 包裹,zh-CN/en-US 两份 json 均有键(跑 i18n 一致性测试)
- 每个按钮有图标;蓝白主题;无裸色值
- 弹窗期间背景推流不冻结;5s/1.5s 超时行为与 spec-auth-business.md 一致
- 720×1280 竖屏无截断;模拟器与板上表现一致
